per printed page, in order: #cover page 1 · full-bleed olive, tone-on-tone monogram + guest name #invitation page 2 · white page inside the oval watercolor wreath #seats page 3 · full-color monogram, seats banner, RSVP deadline #dress-code page 4 · dress code copy + full-bleed inspiration collage #gifts page 5a · full-bleed olive gift block #rsvp -- · shared RSVP form (web-only, no printed equivalent) #faq page 5b · white Q&A block #closing page 6 · full-bleed mauve sign-off Artwork: the watercolor florals are real illustrations shipped with the app, in invitations/static/invitations/wildflower/ — the wreath, the monogram, and three corner sprigs, as transparent WebP. They are versioned in the repo, so there is no upload step and no object storage to configure; WhiteNoise serves them straight out of STATIC_ROOT. Each of the three slots is overridable by the host through a URL field (monogram_image_url / wreath_image_url / sprig_image_url), and blank simply means "use the bundled artwork". Color: every visible color resolves either to a palette-driven Tailwind token from _theme_head.html (primary / secondary / tertiary / surface-* / on-surface* — the "garden" family tonal scale) or to one of the two --wf-* custom properties defined below, themselves derived from --pal-primary. No hard-coded color is used anywhere except as a literal fallback immediately before the derived declaration, for engines that lack the newer color functions. The botanicals are pre-colored raster artwork and are never recolored by CSS. The one place artwork and palette meet is the cover monogram: page 1 prints it tone-on-tone, so rather than ship a second recolored file the bundled monogram is used as a CSS mask over a --wf-leaf-pale fill, which keeps that treatment palette-driven. A host-supplied monogram is rendered as a plain instead — masking it would mean interpolating a user-controlled URL into inline CSS. Where the print's colors are used as FIELDS — the seats banner, the closing endpaper — and for the names at 44px and up, they are reproduced exactly, including the banner's 2.76:1 white-on-green. That is the source design and it is kept deliberately. Small type is a different job: 11px tracked capitals carry the scanning structure of every section below page 2, so those use the --wf-ink-* variants below, which darken lightness while holding the hue. Type: the "garden" family loads Cinzel (all-caps Roman serif) for body and .font-display, and Pinyon Script for .font-script. Cinzel has no useful lowercase contrast, so small copy leans on wide tracking and loose leading instead of case for hierarchy — that is what makes the printed piece read as expensive. {% endcomment %} {# --- Sticky nav ------------------------------------------------------ #} {% comment %} Two of these links point at sections that only render when the host filled the matching fields in, so each one repeats its section's own condition. {% comment %} Fitting the copy inside the wreath. Measured on the bundled artwork (612x792): the clear centred interior is ~65% of its width by ~63% of its height. Wide screens: the frame is locked to the artwork's own 612/792 aspect so the wreath fills it exactly. At the 1100px cap that leaves ~710px of clear width around the 480px measure, and the whole page-2 copy sits inside the oval exactly as it does in print. Narrow screens: it cannot. 65% of a 390px viewport is 254px, and the full copy set that narrow runs ~950px tall against an interior only ~600px tall. An earlier approach — scaling the artwork to 215% and letting the section clip it — put BOTH floral flanks fully off-screen (their inner edges landed at x = -42 and x = 432), so the oval read as two unrelated floral bands and the top arc printed straight through the subtitle. So the oval frames the hero lockup alone, complete and unclipped, and the ceremony/reception blocks follow it in clear space (see _wildflower_details.html). The most recognisable half of the printed page survives intact instead of the whole of it surviving as a fragment. The crossover is `xl`, NOT `md`. Work it from the interior: the copy is 480px wide and ~795px tall, so an interior big enough for it needs the artwork to be at least 480/0.65 = 738px wide and 795/0.63 = 1262px tall — and since the frame holds 612/792, height is the binding constraint, so the frame has to be ~1128px wide before the copy clears the florals. Switching at `md` (768px) put the subtitle 87% under painted flowers on every tablet and small laptop, and covered the second View Map button almost entirely. 1280 (`xl`) is the first stock breakpoint past the real crossover. A host-supplied wreath won't have the same proportions, so this is a best-effort frame: it is positioned and scaled identically, and the copy keeps its own max-width regardless. {% endcomment %}
{% comment %} min-w-0 overrides a flex item's default min-width:auto, so an unusually long hero title set in the oversized script face can't push this box wider than the frame; overflow-wrap then breaks it rather than letting the section's overflow-hidden crop it. The 62% cap is the wreath's clear interior with a little air either side. overflow-wrap:anywhere is right for the prose but WRONG for the names — it will happily split "James" into "Jame / s" once the word is a pixel wider than the box, which at 320px it was. The h1 opts back out below. {% endcomment %}
