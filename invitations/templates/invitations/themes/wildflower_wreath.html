per printed page, in order: #cover page 1 · full-bleed olive, tone-on-tone monogram + guest name #invitation page 2 · white page inside the oval watercolor wreath #seats page 3 · full-color monogram, seats banner, RSVP deadline #dress-code page 4 · dress code copy + full-bleed inspiration collage #gifts page 5a · full-bleed olive gift block #rsvp -- · shared RSVP form (web-only, no printed equivalent) #faq page 5b · white Q&A block #closing page 6 · full-bleed mauve sign-off Artwork: the watercolor florals are real illustrations shipped with the app, in invitations/static/invitations/wildflower/ — the wreath, the monogram, and three corner sprigs, as transparent WebP. They are versioned in the repo, so there is no upload step and no object storage to configure; WhiteNoise serves them straight out of STATIC_ROOT. Each of the three slots is overridable by the host through a URL field (monogram_image_url / wreath_image_url / sprig_image_url), and blank simply means "use the bundled artwork". Color: every visible color resolves either to a palette-driven Tailwind token from _theme_head.html (primary / secondary / tertiary / surface-* / on-surface* — the "garden" family tonal scale) or to a --wf-* custom property defined below, itself derived from the palette CSS variables (--pal-primary / --pal-secondary / --pal-surface / --pal-text) with color-mix(). No hard-coded color is used anywhere except as a literal fallback immediately before the color-mix() declaration, for engines without color-mix() support. The one place artwork and palette meet is the cover monogram: page 1 prints it tone-on-tone, so rather than ship a second recolored file the bundled monogram is used as a CSS mask over a --wf-leaf-pale fill, which keeps that treatment palette-driven. A host-supplied monogram is rendered as a plain instead — masking it would mean interpolating a user-controlled URL into inline CSS. Type: the "garden" family loads Cinzel (all-caps Roman serif) for body and .font-display, and Pinyon Script for .font-script. Cinzel has no useful lowercase contrast, so small copy leans on wide tracking and loose leading instead of case for hierarchy — that is what makes the printed piece read as expensive. {% endcomment %} {# --- Sticky nav ------------------------------------------------------ #}

{% comment %} Fitting the copy inside the wreath. Measured on the bundled artwork (612x792): the largest clear centred rectangle inside the ring is 51% of its width by 63% of its height. Everything below just sizes the artwork so that interior stays bigger than the copy. Desktop: the frame is locked to the artwork's own 612/792 aspect so the wreath fills it exactly. At the 1100px cap that leaves ~560px of clear width, comfortably around the 480px measure. Mobile: the wreath's dense flanks would leave ~170px of measure at 380px, so instead of dropping them the artwork is scaled well past the viewport and the section clips it — the flanks bleed off-screen and only their inner edge frames the copy, which keeps the "enclosed" feeling that defines this page. A host-supplied wreath won't have the same proportions, so this is a best-effort frame: it is positioned and scaled identically, and the copy keeps its own max-width regardless. {% endcomment %}
