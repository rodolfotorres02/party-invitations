{% load i18n %} {% comment %} Shared RSVP form, themed via Tailwind utility classes that pull from the palette-driven config. Used by all seven theme templates. Chrome strings are wrapped with i18n tags. The active language is set by InvitationPublicView / RSVPSubmitView based on `invitation.language`. Reading order is context → decision → qualifier → optional → send: header everything the guest needs BEFORE answering (who it's for, the host's note, the deadline, the adults-only rule, and — on a revisit — what they already said) form "Will you attend?" leads on type size, seats supports it, the message is last because it is the only optional field. The seat allocation is stated exactly once. It used to appear twice — a "This invitation is for 4 guests." line in the header and a "covers up to 4 seats." line 300px below it — which read as a bug. For a multi-seat invitation the number now lives with the seat question that uses it; the header line survives only for the single-guest case, where there is no seat question to carry it. {% endcomment %}
